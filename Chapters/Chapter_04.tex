\section{System Architecture Overview}
%------------------------------

The platform is a Retrieval-Augmented Generation (RAG) \& Tool-Use Agent system specialized for real estate. It follows a "ReAct" (Reasoning + Acting) architecture where a Large Language Model (Gemini) orchestrates specialized geospatial tools to answer user queries.

\begin{itemize}
    \item \textbf{Frontend:} React + TypeScript + MapLibre GL (Visualization) + TanStack Query.
    \item \textbf{Backend:} FastAPI (Python) + LangGraph (Agent Orchestration).
    \item \textbf{Database:} PostgreSQL + PostGIS (Spatial Indexing) + pgvector (Semantic Search).
    \item \textbf{AI Model:} Google Gemini (LLM) + PyTorch Geometric (HGT Valuation Model - Offline).
\end{itemize}

\section{Feature Implementation Details}
%------------------------------

\subsection{Borbann AI Agent (The Core)}
\paragraph{User Experience:}
Users interact via a chat panel overlaying the map. They can attach spatial context (dropping a pin or drawing a bounding box) which is sent to the agent. The UI visualizes the agent's "thought process" by showing which tools are being called (e.g., "Searching properties...", "Calculating transit score...") before streaming the final Markdown response.

\paragraph{Technical Implementation:}
\begin{itemize}
    \item \textbf{Orchestration:} Implemented in \texttt{src/services/agent\_graph.py} using LangGraph.
    \item \textbf{State Machine:} Uses a \texttt{prebuilt.create\_react\_agent} that manages the conversation history and tool execution loop.
    \item \textbf{Context Injection:}
    \begin{itemize}
        \item \textit{System Prompt:} Defines the agent's persona ("Borbann AI"), capabilities, and strict response formatting.
        \item \textit{Spatial Context:} Coordinates (lat, lon) or Bounding Boxes (bbox) from the frontend are injected into the tool arguments.
    \end{itemize}
    \item \textbf{Tools:} The agent has access to a registry of Python functions decorated with \texttt{@tool} for automatic schema generation.
\end{itemize}

\subsection{Location Intelligence Engine}
\paragraph{User Experience:}
Users view a "Livability Report" for any specific point, displaying scores (0-100) for Transit, Walkability, and Schools, along with Flood and Noise risk levels.

\paragraph{Technical Implementation:}
A weighted composite scoring system (Weights: Transit 25\%, Walkability 25\%, Schools 20\%, Flood 15\%, Noise 15\%).
\begin{itemize}
    \item \textbf{Transit Score:} Queries \texttt{transit\_stops} (PostGIS) for nearest rail (<1km), counts bus stops within 500m. Scoring uses a distance decay function.
    \item \textbf{Walkability Score:} Checks density of 8 amenity categories (Restaurants, Cafes, Groceries, Parks, etc.) within 800m using \texttt{view\_all\_pois}.
    \item \textbf{Schools Score:} Queries schools table within 2km, with bonuses for variety of levels.
    \item \textbf{Flood Risk:} Point-in-polygon check against static flood-warning datasets.
    \item \textbf{Caching:} Uses an in-memory dictionary cache keyed by lat/lon grid to prevent re-calculation.
\end{itemize}

\subsection{Site Analysis (Commercial Viability)}
\paragraph{User Experience:}
Business owners select a location and a category (e.g., "Cafe"). The system outputs a "Site Score" indicating commercial potential.

\paragraph{Technical Implementation:}
\begin{itemize}
    \item \textbf{Magnets:} Counts traffic drivers (Malls, Offices, Transit) within 1km.
    \item \textbf{Competitors:} Counts existing businesses of the same category within 1km.
    \item \textbf{Heuristic Formula:} $Score = 50 + (Magnets \times 3) - (Competitors \times 2)$.
    \item \textbf{Traffic Potential:} Classified as High/Medium/Low based purely on Magnet count.
\end{itemize}

\subsection{Catchment Analysis (Isochrones)}
\paragraph{User Experience:}
Displays a polygon on the map representing "How far can I walk/drive in 15 minutes?"

\paragraph{Technical Implementation:}
\begin{itemize}
    \item \textbf{Graph Engine:} Uses OSMnx to load the Bangkok road network graph.
    \item \textbf{Isochrone Generation:} Finds nearest graph node, traverses network based on edge weights (length/speed), and calculates Convex Hull.
    \item \textbf{Population Est:} User PostGIS \texttt{ST\_Intersection} to overlay polygon on population grid.
\end{itemize}

\subsection{Property Search \& Market Stats}
\paragraph{User Experience:} "Find me 3-bedroom houses in Watthana under 10MB."
\paragraph{Technical Implementation:}
\begin{itemize}
    \item \textbf{Search:} Direct translation of natural language parameters into a SQLAlchemy/PostGIS query on the \texttt{house\_prices} table.
    \item \textbf{Market Stats:} Aggregation queries (AVG, COUNT, MIN, MAX) grouped by district.
\end{itemize}
